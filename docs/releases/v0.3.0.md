# v0.3.0 로컬 모니터링 릴리스 노트

v0.3.0은 source checkout에서 실행하는 로컬 보안 로그 조사 보조 도구다. 단일 application 또는 SSH 파일의 새 줄을 분석하고 탐지 관찰, 지원 관계, 위험도, 조사 사례를 구분해 보여 준다. 이 결과는 공격 성공·계정 탈취·침해 확정이 아니며, 로그에 없는 행위나 인과관계를 증명하지 않는다.

## 설치와 주요 흐름

Python 3.12 이상과 uv를 준비하고 저장소의 clean source checkout에서 실행한다.

```bash
uv sync --locked --dev
uv run python -m app.monitor_setup
uv run python -m app.local_web --monitor
```

설정 마법사는 읽을 수 있는 application 로그 **하나만** 등록한다. 개인정보 안내, bounded dry-run, 미리보기, 명시적 저장 승인을 거친다. 실행 전 기존 줄은 분석하지 않으며 새 설정의 최초 시작은 `FROM_END`다. 설정 생성은 서버 자동 시작이 아니다. 기본 설정의 안전한 상태 요약, 승인 삭제, 분석 연속성을 포기하는 checkpoint reset은 각각 다음 명령으로 수행한다.

```bash
uv run python -m app.monitor_setup --show
uv run python -m app.monitor_setup --delete
uv run python -m app.monitor_setup --reset-checkpoint
```

`--show`는 원본 경로·JSON을 출력하지 않는다. `--delete`는 승인한 기본 설정과 연결 checkpoint만 삭제하며 원본 로그는 보존한다. `--reset-checkpoint`는 승인한 derived checkpoint 하나만 삭제하고, 다음 실행은 현재 파일의 `FROM_END`에서 과거 분석 상태와 관계·위험도·사례·SSE replay가 이어지지 않는 새 epoch다. 두 명령은 secure erase가 아니며 backup·filesystem snapshot·crash dump에 남을 수 있다. 실행 중인 monitor의 lock이 있으면 reset을 거부한다.

SSH는 **별도로 준비한 private 단일 source v2 기본 설정**에서 bounded checkpoint 복구가 가능하다. 설정 마법사는 아직 SSH 설정을 만들지 않는다. 명시적 v1 SSH 또는 application 설정은 `uv run python -m app.local_web --monitor-config <절대-경로>`로 실행하고 기존 `FROM_END` 의미를 유지한다. 기본 `uv run python -m app.local_web`에서는 live 기능이 켜지지 않는다. `access`는 live detection-only이고 SSH의 file-access 관계나 cross-source 분석은 없다.

## 재시작, 개인정보와 저장

새로운 checkpoint-enabled v2 설정은 같은 regular file identity와 bounded 원본 구간이 유지될 때만 `bounded replay`로 분석 prefix를 재구성한다. 원본 줄을 checkpoint에 복사하지 않으며 과거 SSE publication도 재전송하지 않는다. Checkpoint에는 private 파일 identity·byte 위치·안전한 의미 검증 metadata가 저장된다. 원래 로그 경로는 private config에 저장되므로 공유하지 말아야 한다. 분석 중 원문이 프로세스 메모리에는 존재할 수 있지만 공개 API·SSE·UI에는 allowlist 기반 요약만 보낸다. 외부 LLM 자동 전송은 없다.

파일 교체, rotation, copytruncate, truncation, checkpoint 불일치·권한 오류는 자동 병합하지 않고 중단한다. 안전하지 않은 상태를 0건 또는 안전으로 표현하지 않는다. 재시작 전후 중복이나 gap이 가능하고 강제 종료·전원 차단에 대한 crash recovery, exactly-once, 무유실은 보장하지 않는다. 별도 collector, 다중 source 동시 모니터링, cross-source 상관분석 및 hosted 실제 로그 업로드는 지원 범위 밖이다.

## 업그레이드와 검증 범위

기존 application v2 설정·checkpoint는 자동 migration·재작성 없이 읽는다. `DISABLED`인 기존 설정과 명시적 v1 설정은 재시작 시 계속 `FROM_END`다. SSH bounded checkpoint는 private 기본 v2 설정에서만 활성화한다. 기존 v0.1.0·v0.2.0 배치·로컬 웹 기능은 유지한다.

Phase 26.1 Ubuntu 기준 SHA의 전체 회귀는 **2,343 passed, 기존 경고 2개**였고, 합성 인증·웹 **79/79**, Linux Audit **21/21**, risk/case **70/70**을 확인했다. Ubuntu의 별도 CLI/server 프로세스 SSH 재시작·lock·reset smoke와 application checkpoint focused 검증도 통과했다. v0.3.0 후보의 macOS detached clean checkout은 locked 설치, 전체 **2,347 passed·기존 경고 2개**, 같은 세 합성 평가와 application·SSH loopback smoke를 통과했다. 실제 Safari WebDriver는 두 live 역할의 단계적 결과 적용을 확인했지만 사용자 keyboard-only·확대·VoiceOver 검수는 대체하지 않는다. 이 검증은 실제 운영 로그 탐지율이나 모든 Linux filesystem의 동작을 증명하지 않는다. Hypothesis와 Schemathesis는 개발 테스트에만 있고 dependency evidence bundle은 공식 취약점 release gate가 아니다.

설치 방식은 source checkout만 검증했다. `uv build`의 기존 flat-layout 문제가 남아 wheel/PyPI 배포를 제공하지 않는다. Safari의 새 v0.3.0 live·재시작 UX에서 keyboard-only, 실제 200% 확대, Web Inspector, VoiceOver 상세는 별도 수동 검증이 필요하다. WCAG 2.2 AA 준수를 주장하지 않는다. 민감한 취약점은 [SECURITY](../../SECURITY.md)에 안내된 GitHub 비공개 신고 경로를 사용하고, 실제 로그·credential·개인정보를 공개 issue에 첨부하지 말아야 한다.
