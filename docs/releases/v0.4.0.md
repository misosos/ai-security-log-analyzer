# v0.4.0 로컬 조사 작업 화면 릴리스 노트

v0.4.0은 source checkout에서 실행하는 방어 목적의 로컬 보안 로그 조사 보조 도구다. 이 버전은 사용자가 목적·현재 상태·다음 행동과 결과의 근거를 더 쉽게 찾도록 웹 화면을 정리한다. 탐지 관찰은 조사 후보이며 침해·공격 성공의 확정이 아니다. 관련 활동은 인과관계를 증명하지 않고, 결과가 없거나 위험도가 내려갔다고 안전 또는 해결을 뜻하지 않는다.

## 설치와 사용

Python 3.12 이상과 uv를 준비한 뒤 source checkout에서 실행한다.

```bash
git clone https://github.com/misosos/ai-security-log-analyzer.git
cd ai-security-log-analyzer
uv sync --locked --dev
uv run python -m app.local_web
```

브라우저에서는 loopback `http://127.0.0.1:8000/`을 사용하고 `Ctrl+C`로 종료한다. **예시 데이터로 둘러보기**와 **내 로그 분석하기**를 구분해 선택할 수 있다. Application 로그 하나의 private 설정을 준비해 live 분석을 시작하려면 `uv run python -m app.monitor_setup` 뒤 `uv run python -m app.local_web --monitor`를 사용한다. SSH 설정 마법사는 제공하지 않으며 별도로 준비한 private 단일 source 설정이 필요하다. 배포·설치 지원 범위는 source checkout뿐이고 wheel/PyPI 패키지는 제공하지 않는다.

## 달라진 조사 화면

- 전체 폭 investigation workspace의 **왼쪽 탐색**에서 작업을 고르면 오른쪽에 선택한 화면만 보인다. 기본 실행에서는 live 메뉴를 숨기고, 결과 메뉴는 표시할 결과가 생긴 뒤에만 나타난다. 화면 전환은 분석 요청이나 EventSource 연결을 새로 만들지 않는다.
- 시작 화면은 예시 데이터, 내 로그 분석, Linux Audit의 세 행동 카드를 비교하고 **예시 데이터 → 내 로그 분석 → 결과 확인** 흐름을 이해하도록 돕는다. 내부 revision·replay gap 같은 용어 대신 현재 상태와 복구 행동을 사용자 언어로 표시한다.
- 결과 상단에는 확인할 활동·관련된 활동·조사 사례·별도 확인의 네 안전한 집계를 표시한다. 넓은 화면에서는 조사 사례 두 개를 나란히 비교한다. 사례의 기본 카드에는 위험도와 신뢰도, 주요 활동, 관련 활동 수, 짧은 KST 시간 범위를 둔다. **상세 보기**에는 관계 설명, KST/UTC 전체 시각, 근거와 시간순 기록을 보존한다.
- 선택한 Lucide SVG 아이콘만 self-hosted 형태로 포함하고 한국어 텍스트 레이블을 유지한다. 아이콘 이름이나 색상만으로 상태를 전달하지 않으며 외부 CDN·font·runtime fetch를 추가하지 않는다. HTML 보고서 다운로드와 기존 분석 결과의 의미는 그대로다.

## 검증 범위

개발 테스트에서 axe-core와 Playwright를 production bundle과 분리해 사용한다. 합성 데이터로 렌더링한 Chromium의 13개 주요 상태에서 자동 검출 위반과 외부 요청이 0건이었다. 키보드·focus·scroll·reduced-motion 및 320/640/1024/1440 CSS px viewport의 가로 넘침도 별도 자동 회귀로 확인했다. 이는 모든 접근성 문제나 실제 Safari 동작을 증명하지 않는다.

[Safari 18.6 직접 수용 기록](../ui_safari_acceptance_28_5.md)에서는 메뉴와 시작 행동, 네 결과 지표와 조사 사례 비교, 상세 disclosure의 Enter·Space 조작, **Option+Tab**, 실제 **200%** 페이지 확대, Safari의 가능한 최소 창 너비, VoiceOver의 landmark·요약·disclosure 일부, Web Inspector의 JavaScript/CSP/MIME·외부 요청·중복 EventSource·개인정보 경계를 사용자에게 확인받았다. 정확한 Safari **320 CSS px** viewport와 VoiceOver **전체 페이지 읽기**는 **NOT_TESTED**다. axe/Playwright 자동 통과나 일부 수동 검수를 **WCAG 2.2 AA 준수** 선언으로 해석하지 않는다.

합성 인증·웹 평가는 79/79, Linux Audit는 21/21, risk/case는 70/70으로 기존 결정적 의미를 확인했다. 이 수치는 실제 운영환경 탐지율이나 모든 공격·장애에 대한 성능을 뜻하지 않는다. 자동 검증과 수동 Safari 증거의 구분 및 남은 범위는 [docs 문서 지도](../index.md)에 연결된 수용 기록에 있다.

## 개인정보와 알려진 한계

실제 로그는 기본적으로 로컬에서 처리하고 외부 LLM을 자동 호출하지 않는다. 원본 계정, IP, username, hostname, 로그·설정·checkpoint 경로, HTTP path/query와 원문은 공개 API·SSE·UI·오류에 새로 투영하지 않는다. 분석 중 원본은 trusted 내부 처리나 메모리에 남을 수 있으며 HTML 보고서와 private 설정·checkpoint는 민감한 자료로 취급해야 한다. 공개 Issue에 실제 로그·credential·개인정보를 올리지 말고 [SECURITY](../../SECURITY.md)의 비공개 취약점 신고 경로를 사용한다.

Live 분석은 application 또는 SSH 단일 파일에 한정된다. Rotation·copytruncate 자동 복구, 다중 source·cross-source 분석, 강제 종료 뒤 exactly-once·무유실은 보장하지 않는다. Access live는 detection-only이며 Linux Audit는 별도 조사 흐름이다. 공격 성공·계정 탈취·파일 유출 여부는 로그만으로 확정하지 않는다. Hosted 업로드·자동 대응 시스템 및 wheel/PyPI 배포는 지원하지 않는다. [v0.3.0 릴리스 노트](v0.3.0.md)의 checkpoint 경계와 [v0.3.0 Safari 수용 기록](../v030_safari_acceptance_27_1.md)은 이전 기능의 증거로 유지한다.
