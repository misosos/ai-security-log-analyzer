# v0.1.0 로컬 릴리스 노트 초안

상태: 공개 전 검토 초안. 태그·GitHub Release·PyPI 배포는 아직 없다. `pyproject.toml`의 프로젝트 버전 `0.1.0`은 API/평가 schema version과 별개다. 라이선스는 [MIT](../../LICENSE)이며 저작권 표기는 `Copyright (c) 2026 misosos`다. GitHub Private vulnerability reporting은 사용자 확인에 따라 활성화됐다. Safari 수동 검증과 원격 CI는 공개 릴리스 전 남은 gate다.

## 무엇을 만들었고 누구를 위한 버전인가

이 도구는 macOS/Linux의 한 사용자가 자신의 컴퓨터에서 보안 로그를 초기 검토하는 로컬 보조 도구다. 학습자와 주니어 분석가가 샘플 또는 작은 실제 로그를 분석하고, 조사 사례·시간순 조사 흐름·근거·한계·다음 조사 단계를 본 뒤 대상별 HTML 보고서를 저장할 수 있다. 이 도구는 조사 우선순위를 정하는 로컬 보조 도구이며 침해 사실, 공격 성공, 공격자 신원 또는 인과관계를 확정하지 않는다.

Hosted SaaS, 조직용 다중 사용자 시스템, 실시간 SOC 제품, 자동 대응 도구 또는 침해 판정 도구가 아니다.

## 5분 빠른 시작

Python 3.12와 `uv`를 설치한 macOS/Linux에서 source checkout으로 실행한다. `uv build`는 현재 flat-layout package discovery에서 실패하므로 wheel/PyPI 설치를 안내하지 않는다.

```bash
git clone https://github.com/misosos/ai-security-log-analyzer.git
cd ai-security-log-analyzer
uv sync --locked --dev
uv run python -m app.local_web
```

브라우저가 자동으로 열리지 않으면 `http://127.0.0.1:8000/`을 직접 연다. 자동 열기를 원하지 않으면 `uv run python -m app.local_web --no-browser`를 사용한다. 웹에서 먼저 **샘플로 체험하기**를 누른다. 실제 로그는 로컬 서버에서만 **내 로그 분석하기**의 애플리케이션 인증, SSH 인증, 웹 접근 세 칸에 각각 선택한다. 연습에는 `sample_logs/brute_force.log`, `sample_logs/ssh_auth.log`, `sample_logs/web_shell.log`를 같은 순서로 사용한다. 종료는 서버 터미널의 **Ctrl+C**다. `0.0.0.0` 바인딩·포트 포워딩을 하지 않는다.

## 주요 기능과 경계

- Brute Force, Password Spraying-like, Path Traversal, SQL Injection-like, XSS-like, Sensitive Resource Probing-like, Web Scanning-like 탐지 관찰과 인증 실패·성공 상관분석. 네 새 웹 유형은 독립 관찰이며 공격 성공을 뜻하지 않는다. 여러 성공 후보는 기존 범위 안의 가장 가까운 후속 성공을 결정적으로 선택한다.
- 기존 위험도와 별도 신뢰도, 근거·해석 한계, 조사 사례·Timeline, 안전하게 결합하지 않은 독립 관찰.
- UTF-8 standalone HTML 다운로드. 현재 보고서는 **대상별 결정적 조사 보고서**이며 사례 Timeline 전체를 담은 보고서가 아니다.
- Linux Audit는 선택적 CLI aggregate와 네 가지 실행 조사 후보 category 경계다. 새 category는 기본·선택적 보안 Linux Audit API, 웹, HTML, LLM에 추가되지 않으며 인증·웹 사례와 결합되지 않는다. 기본 웹 업로드에 Linux Audit는 포함되지 않는다. 기존 LLM 설명 코드는 분리되어 있으며 기본 웹·CLI 분석이 외부 AI를 호출하지 않는다.

## 개인정보 처리

로컬 업로드는 요청별 private 임시 디렉터리(`0700`)와 고정 내부 파일(`0600`)에 잠시 staging한다. 정상·검증 실패·분석 실패·취소·timeout의 알려진 경로에서 정리한다. 로그·결과·HTML을 서버 DB나 영구 결과 저장소에 두지 않는다. 비정상 프로세스/호스트 종료 뒤 orphan 임시 파일 삭제는 보장하지 않는다. 브라우저 결과는 현재 탭 메모리이며 HTML은 사용자 클릭 시 다운로드된다. 다운로드 파일은 민감한 조사 자료이므로 저장·공유·삭제 위치를 직접 관리해야 한다.

공개 projection에는 원래 계정, 원래 HTTP path, full query와 raw log가 들어가지 않는다. 다만 trusted internal `analyze()` 결과에는 계정 join을 위해 원문이 남을 수 있다. Python 메모리의 안전 삭제를 보장하지 않는다. Deprecated `/api/analyze`의 raw nested 값을 읽던 소비자는 [migration 안내](../public_analysis_privacy.md)를 참고해야 한다.

## 합성 평가 결과

오프라인 `synthetic_boundary_corpus` 79/79 시나리오가 통과했다(기존 43개 ID 유지). Parser는 200줄 중 parsed 195·ignored 2·rejected 3, 예상 밖 parse/rejection 0, risk·case는 각 70/70이다.

| 관찰 | TP | FP | FN | TN | precision | recall | F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Brute Force | 11 | 0 | 0 | 58 | 1.0 | 1.0 | 1.0 |
| Password Spraying-like | 2 | 0 | 0 | 67 | 1.0 | 1.0 | 1.0 |
| Path Traversal | 2 | 0 | 0 | 67 | 1.0 | 1.0 | 1.0 |
| SQL Injection-like | 5 | 0 | 0 | 64 | 1.0 | 1.0 | 1.0 |
| XSS-like | 5 | 0 | 0 | 64 | 1.0 | 1.0 | 1.0 |
| Sensitive Resource Probing-like | 4 | 0 | 0 | 65 | 1.0 | 1.0 | 1.0 |
| Web Scanning-like | 3 | 0 | 0 | 66 | 1.0 | 1.0 | 1.0 |

표의 precision·recall·F1은 **포함된 작은 합성 라벨 범위에서의 구현 일치도**다. 실제 운영환경 탐지율이 아니며 일반화할 수 없다. Web Scanning-like positive support는 정확 임계값·초과·60초 경계의 3개다. permutation은 별도 불변식이며 support에 포함하지 않는다. 상관관계는 Failed Login → Success TP 6, Brute Force → Success TP 3, Spray → Success TP 1이며 각 FP/FN은 0이다. 이는 인과관계나 공격 성공률이 아니다. 재현: `uv run python -m app.evaluation --format text`.

별도 Linux Audit 프로세스 실행 분류 합성 평가는 21/21 시나리오, category 관찰 수는 셸 4·전송 도구 4·권한 변경 도구 3·임시 위치 4이다. 한 실행이 둘 이상 category일 수 있다. 이는 악성 탐지 성능이 아니며 기존 79개 IP 기반 confusion matrix에 포함하지 않는다.

## 알려진 제한과 보안 주의

각 실제 로그 파일은 32 KiB, 합계 80 KiB, multipart envelope 96 KiB, 한 줄 2048바이트·파일당 512줄까지다. Archive·Linux Audit 웹 업로드·실시간 collector·syslog·queue/SSE/WebSocket·SIEM 연동·antivirus·자동 대응은 없다. ASGI/프록시의 사전 allocation을 앱이 완전히 제한하지 못하며 rate limit은 여러 worker를 통합하지 않는다. 평가 수치를 실제 운영 성능으로 일반화하지 않는다. WCAG 2.2 AA와 운영 SLA를 주장하지 않는다. 취약점 신고는 [SECURITY](../../SECURITY.md)의 확인된 경로를 사용해야 하며 실제 로그·credential을 공개 issue에 올리지 않는다.

## 업그레이드와 삭제

먼저 서버를 Ctrl+C로 종료한다. 업데이트 전 `git status`를 확인하고 수정·미추적 보고서가 있으면 보존 방법을 결정한다. Clean working tree에서만 다음을 실행한다.

```bash
git pull --ff-only
uv sync --locked --dev
```

삭제할 때는 다운로드한 HTML 보고서의 저장 위치를 먼저 확인한다. 저장소를 지우더라도 브라우저 다운로드 파일은 자동 삭제되지 않는다. 저장소 디렉터리 제거는 사용자가 내용을 확인하고 명시적으로 선택한다. 복사·실행용 재귀 삭제 명령은 제공하지 않는다.
