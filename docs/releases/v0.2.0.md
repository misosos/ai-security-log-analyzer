# v0.2.0 로컬 실시간 모니터링

v0.2.0은 기존 로컬 보안 로그 조사에 승인한 **단일 파일의 새 줄**을 제한된 메모리에서 자동 분석하는 기능을 더한다. 탐지 관찰, 지원되는 관계, 기존 위험도 평가와 조사 사례는 조사 보조 정보다. 공격 성공·계정 침해·인과관계 또는 확정 사고를 뜻하지 않는다.

## 시작 방법

Python 3.12 이상과 `uv`를 사용해 source checkout에서 실행한다. 개인 로그를 저장소에 추가하지 않는다.

```bash
git clone https://github.com/misosos/ai-security-log-analyzer.git
cd ai-security-log-analyzer
uv sync --locked --dev
uv run python -m app.local_web --monitor-config /absolute/path/to/live-monitor.json
```

[안전한 config 예시](../examples/live-monitor.json)를 복사한 뒤 config와 로그 source의 절대 경로를 자신의 로컬 파일로 수정한다. V1 config는 승인한 source 하나와 `FROM_END`만 허용한다. 실행 전에 있던 줄은 분석하지 않는다. 기본 서버 주소는 `http://127.0.0.1:8000/`이며 `--no-browser`와 `--port 8123`을 함께 사용할 수 있다. 종료는 서버 터미널에서 `Ctrl+C`다. `--monitor-config`를 생략하면 live endpoint는 비활성이고 기존 샘플·3파일·Linux Audit 단일 파일 분석은 그대로 사용할 수 있다.

## 실시간 처리와 화면

Tail poll은 완성된 UTF-8 줄만 bounded queue로 옮긴다. 단일 lease에서 기존 parser와 detector를 실행하고 application source에서는 기존 correlation·risk·case를 전체 bounded prefix로 재계산한다. 모든 후보를 준비한 뒤 queue ack를 수행하고 detection·analysis state를 commit하며 두 종류의 변경이 있으면 하나의 사전 검증된 publication batch로 게시한다. Ack 이후의 실패는 rollback이나 자동 재처리로 숨기지 않고 terminal 상태로 표시한다.

브라우저는 `observation_changes`의 탐지 관찰과 `analysis_changes`의 지원 관계·기존 위험도·조사 사례를 구분한다. 새 event를 즉시 목록에 삽입하지 않고 **새 결과 N건 보기**를 누를 때 제한된 대기열을 적용한다. **화면 업데이트 일시 정지**는 화면 반영만 멈추며 서버 로그 수집은 계속될 수 있다. 변경 기록이 buffer에서 제거되면 replay gap을 명시하고, 오래된 상세를 최신으로 취급하지 않으며 최신 snapshot 기준의 수동 복구를 안내한다.

## 개인정보와 저장 경계

Status·SSE·브라우저 결과는 고정된 안전 필드만 사용한다. 원래 계정, IP, HTTP path/query, raw line, 원본 근거·내부 subject key·hash·로그 파일 경로는 공개하지 않는다. 다만 join과 detector 계산을 위한 trusted process memory에는 원문이 존재할 수 있으며 Python 메모리의 secure erase는 보장하지 않는다. 원본 로그·결과를 서버 DB에 영구 저장하지 않는다. 다운로드한 기존 HTML 보고서는 사용자가 별도로 보관·삭제해야 한다. 실사용 로그·credential을 공개 issue나 지원 요청에 첨부하지 않는다.

## 검증된 범위

단일 application live prefix의 기존 batch detection·correlation·risk·case 의미, 제한된 publication batch·replay/gap, status/SSE 개인정보 경계, 기존 샘플·3파일·Linux Audit 흐름을 자동 회귀와 합성 평가로 확인했다. 합성 인증·웹 79/79, Linux 21/21, risk/case 70/70은 작은 고정 평가 corpus의 일치도이며 운영환경 탐지율이 아니다. Safari 18.6에서 사용자는 keyboard-only 핵심 조작, 실제 200% 확대, 가능한 최소 창 너비, 주요 Inspector 흐름, pause 중 append, replay gap·종료 뒤 수동 복구를 확인했다. 정확한 320 CSS px 측정과 VoiceOver 상세 읽기는 별도 검증 범위이고 WCAG 2.2 AA 준수를 주장하지 않는다. 측정 수치는 개발 환경 참고값이지 운영 SLA가 아니다.

## 알려진 제한

Live correlation·risk·case는 application source 하나에만 적용된다. SSH/access live는 기존 detection-only이며 Linux Audit live, cross-source 결합, 자동 대응, 사건 확정, hosted/multi-tenant 노출은 지원하지 않는다. Process-local·memory-only session과 bounded replay에는 crash recovery가 없어 process crash·재시작 중 누락을 복구하지 못하고 여러 worker 간 공유도 없다. Exactly-once나 무유실이 아니며 느린 client와 eviction은 replay gap을 만들 수 있다. 새 로그마다 LLM을 호출하지 않는다.

## 설치와 보안 신고

지원 설치 방식은 **source checkout + `uv sync --locked --dev`**다. 현재 flat-layout의 `uv build` package discovery 실패가 있어 wheel/PyPI 설치는 지원하지 않는다. 라이선스는 [MIT](../../LICENSE)이며 보안 취약점은 [SECURITY](../../SECURITY.md)의 비공개 신고 경로를 사용한다.

## v0.1.0에서 달라진 점

v0.1.0의 합성 샘플·3파일 로컬 분석·Linux Audit 별도 분석·조사 보고서에, `--monitor-config` 단일 source의 새 줄 수집과 bounded 분석, 안전한 SSE 재연결 및 단계적 실시간 UI가 추가됐다. 기존 배치 규칙·threshold·위험도·case grouping의 의미는 변경하지 않는다.
